## 1. socat is gone: git-over-SSH on macOS now uses `/usr/bin/nc`

Upstream #681 (v0.0.80). When the proxy wants a token and the SOCKS and HTTP listeners
are the same port (always true for the CLI's mux proxy), macOS gets two variables:

```
SRT_SSH_PROXY_COMMAND=LC_ALL=C; no() { ... }; ... | /usr/bin/nc 127.0.0.1 <port> | ...
GIT_SSH_COMMAND=ssh -o ControlMaster=no -o ControlPath=none -o ProxyCommand="/bin/sh -c 'eval \"\${SRT_SSH_PROXY_COMMAND:?unset, but GIT_SSH_COMMAND needs it}\"' sh '%h' %p"
```

The script sends an authenticated `CONNECT host:port` with `Proxy-Authorization: Basic …`
over nc, reads the response head, and either execs `cat` to relay or prints the status
line to stderr and exits. The token travels in a variable, not in ssh's argv. Without a
token (external SOCKS proxy) the old `nc -X 5` spelling is still used.

Verified through the real `_ccx_run` wrapper with `/opt/homebrew/bin` off `PATH`:

```
$ git ls-remote git@github.com:ubc/sandbox-runtime.git HEAD      # denyall and allowall
17e438ba09021a80ffbb4bcb1ff4f340bdf158a3	HEAD
$ eval "$GIT_SSH_COMMAND -T git@github.com"                      # README recipe for plain ssh
Hi smolyn-ubc! You've successfully authenticated, but GitHub does not provide shell access.
$ eval "$GIT_SSH_COMMAND -T git@gist.github.com"                 # deny reason arrives in-band
sandbox proxy: gist.github.com:22: 403 Creating gists is blocked by sandbox policy (exfiltration risk). Write to a file in the repo instead.
```

Bare `ssh github.com` still fails with "Could not resolve hostname" as before: only the
`GIT_SSH_COMMAND` spelling carries the ProxyCommand.

## 2. Refused CONNECTs say why, in the status line

Also #681. The `403` that answers a refused CONNECT carries the deny reason as its status
phrase, cleaned the way violation lines are (non-ASCII becomes `?`). `curl -I` shows it
directly, ssh prints it via the script above, git prints it as the proxy error. Example:

```
$ curl -sI https://gist.github.com | head -1
HTTP/1.1 403 Creating gists is blocked by sandbox policy (exfiltration risk). Write to a file in the repo instead.
```

The violations file gets the same line (`deny network-outbound gist.github.com:443 (…)`),
so the agent now sees the reason twice: in the tool output and in the PostToolUse hook.
Filesystem denials still reach the agent only through the hook.

## 3. Behaviour changes relevant on macOS (no config edit needed)

- **Node ≥ 22.12 is required** (#636). Local Node is 24.
- **Glob brackets** (#620–#622, #687, #718): a path entry whose characters read as a
  pattern is also read as the path it spells, where that exists; brackets that spell no
  character set (`[user-id]`, `backup[2024-01-15]`, `list[].ts`) are text; a `*` or `?`
  inside brackets is a member of the set. New `{ "path": "...", "literal": true }` form in
  all four filesystem lists marks an entry as a name whatever it holds. Neither ccx config
  has bracketed paths. The types changed accordingly (`FilesystemPathEntry[]`), but the
  fork's unrecognized-key walker skips unions, so the object form is not flagged.
- **Read rules apply under both spellings of a path** on macOS (#680): as written and
  with the symlinks on the way resolved.
- **`credentials.files` entries beat `allowRead`/`allowWrite`** on every platform (#680,
  #686). ccx does not use `credentials.files`.
- **Library self-protection** (#595): a wrapped command is write-denied the library's own
  install directory, and `checkDependencies()` warns when srt is installed where the
  sandbox can write. Under nvm that is `~/.nvm/...`, which neither config grants write
  to. No new violation noise observed.
- **TLS termination runs in-process** (#665, #700): no per-tunnel listener; new
  `tlsTerminate.maxTunnels` (default 256; a CONNECT past it gets `503` with
  `X-Proxy-Error: too-many-tunnels` and a violation) and `handshakeTimeoutMs` (default
  10000). Needs Node or Bun ≥ 1.4.
- **Proxy robustness**: an upstream that answers with an invalid status line gets `502`
  instead of crashing the proxy (#660); an upstream that sends more than its
  `Content-Length` no longer loses its answer (#717); certificate serials never start with
  a zero byte (#685).
- **Temp files**: `process.exit()` or a failed `initialize()` no longer leaves the
  library's temp objects (a generated CA key among them) behind (#670). ccx uses a
  persistent CA via `caCertPath`/`caKeyPath`, unaffected.
- **Ask callback** only allows on `true` (#591). The CLI has no callback; no impact.

## 4. New options worth considering for the ccx configs

- **`network.requireHostMatch: true`** (#663): answer `421` to a request whose Host
  header, SNI or absolute-form authority does not name the host and port it is sent to.
  Refusals are recorded as violations. Cheap hardening around credential injection.
  Recommended to trial in `denyall` first, then both, and re-run `just check` plus
  npm/cargo/uv/gh smoke tests.
- **`deniedDomains: ["github.com:22", "ssh.github.com"]`** with reasons: closes the SSH
  path that bypasses token masking. Now that the reason reaches ssh in-band (section 1)
  the failure is self-explanatory. Still a policy choice: SSH is the documented push path
  today.
- **`ignoreViolations` noise**: this sync's smoke runs showed three recurring benign
  lines from ssh and its `$SHELL -c` ProxyCommand hop under `denyall`:
  `mach-lookup com.apple.dnssd.service`, `mach-lookup com.apple.usymptomsd`, and
  `file-read-data /Users/<you>/.zshenv`. Optional additions.

Not adopting, and why:

- `refuseOpaqueTunnels` refuses every CONNECT the proxy cannot see into, SSH included.
- `stripResponseHeaders`, `allowPlaintextHeaderSet`, `ambiguousRequestTarget` only
  matter with a `filterRequest` callback, which is a library API.
- `credentials.files` masking still degrades to deny on macOS.

## 5. New upstream capabilities (library / embedder level)

These do not reach the CLI configs but change the "future directions" picture:

- **Per-command network allow lists** (#591): `registerCommandNetworkLists(commandId,
  { allowedDomains })`, keyed by the proxy username the wrap presents. The primitive for
  "npm reaches only `*.npmjs.org`".
- **`filterRequest` can rewrite and observe** (#663): an allow may carry
  `removeHeaders`, `setHeaders`, `onResponse`; a deny may choose its status; the callback
  gets `scheme`, `sni`, `target`, `requestTarget`, `rawHeaders`. URL-level policy.
- **`srt proxy` / `srt-proxy`** (#666, #668): the HTTP proxy alone, with an external
  decider process answering every request (`docs/srt-proxy.md`). The "external policy
  engine" idea, upstreamed.
- **`network.ambiguousRequestTarget`** (#698): `refuse` (default) / `asSpelled` /
  `normalize` for targets that name another path once normalised.
- New export `realPathOf` (#683); `writeRootsOf()` for every write root (#621).

## 6. Linux-only changes (for the "Using on Linux" notes)

- **Sandboxed commands stay in their namespaces** (#588, #617): no new user or mount
  namespaces by default, so Chromium/Electron's sandbox, rootless podman/buildah, nested
  bubblewrap and `unshare -r` fail inside. `allowNestedUserNamespaces: true` lifts it (at
  the cost of the write denies against a hostile command). Needs the seccomp helper, or
  bubblewrap ≥ 0.8.0 not installed setuid.
- **`denyWrite` beats `allowWrite` however nested** (#684): `denyWrite: ["~"]` makes a
  project under `~` read-only; `denyWrite: ["/tmp"]` makes the sandbox's own `TMPDIR`
  read-only.
- **Dangerous names** (`.bashrc`, `.git/config`, `.vscode/`) are write-denied one level
  below the working directory whatever else the tree holds (#629).
- **Glob walk** is ~6× faster, yields to the event loop every 10 ms, honours the
  `AbortSignal`, and restarts if the config or cwd changes mid-wrap (#627, #628, #638,
  #644, #645, #655, #679).
- **Fixes**: bubblewrap 0.4 starts again (#580); a command starts only once both relays
  listen (#639); relays fall back to IPv4 without IPv6 (#719); `AF_VSOCK` is refused
  (#691); a file above a write deny is kept read-only (#705); empty placeholder mounts are
  removed when the last sandbox ends (#671); `denyRead` patterns work on file systems
  whose listings carry no entry types (#672).

## 7. v0.0.81 is Windows-only

Write-restricted token, profile read grant (`srt-win profile …`), `--allow-loopback`,
AppContainer and stdin-pipe escapes closed, kept ACL grants, lower-case-only proxy
variables, `NODE_USE_ENV_PROXY=1`. Nothing changes on macOS or Linux.
